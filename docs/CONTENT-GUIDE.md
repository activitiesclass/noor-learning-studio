# إضافة منهج وتطوير الدروس

## ابدأ من المصادر

اجمع الكتاب ودليل المعلم وتوزيع الحصص وخيارات أهداف نور الرسمية. اكتمل محتوى السادس وفق الكتاب ودليل المعلم والخطة، واكتمل محتوى الخامس وفق الكتاب ودليل المعلم والخطة، بينما أصبح محتوى التاسع للفصل الأول مكتملًا وتبقى أهدافه الرسمية بحاجة إلى المطابقة داخل نور.

من الموقع: افتح استوديو التطوير، وأنشئ مسودة منهج أو درس. المدخل الحالي ينشئ لقاءً تجريبيًا من حصتين، ولا يقرر لك عدد حصص الدليل؛ راجع التوزيع وأضف اللقاءات اللازمة في بيانات المشروع. تبقى المسودة غير قابلة لتعبئة نور حتى اعتمادها.

## المخطط

- course: grade، subject، semester، status، units.
- unit: title، noorTitle، officialPeriods، source، lessons.
- lesson: title، noorTitle، officialPeriods، source، goalSource، quiz، meetings.
- meeting: id، part، title، goalBinding، parentNote، periods.
- period: أهداف موزعة، موقف بداية، شرح، مثال، مهمة، خطأ شائع، تدخل، نشاط، دليل تعلم، سؤال ومعيار، مراحل 40 دقيقة.

المعرفات إنجليزية ثابتة وغير مكررة. تبقى noorTitle مطابقة لاسم الشجرة الرسمي؛ تعديل العنوان التعليمي لا يغيرها تلقائيًا. يرفض المستورد نصوص HTML داخل المحتوى؛ التنسيق ينتج من القالب المركزي. استخدم النصوص المجردة وليس إدراج سكربتات.

## حالات الاعتماد

- course.status = planned: مسار بلا محتوى.
- draft: منهج تحت المراجعة.
- ready: منهج راجع المعلم مصدره.
- lesson.goalSource = draft: أهداف غير معتمدة.
- teacher-guide: أهداف من الدليل دون ادعاء رصد معرف نور.
- noor-observed: أهداف مرصودة من النموذج مع معرفها الحقيقي.
- meeting.goalBinding = draft يمنع التعبئة.
- review يستلزم مراجعة الأهداف يدويًا، وخصوصًا المشروع.
- official لا يقبل دون noor-observed ومعرفات رقمية رصدت فعلًا.

## توزيع ثلاث حصص على أسبوعين

أنشئ لقاءين، حصتين في كل لقاء. علّم الحصة الرابعة reinforcement: true، وابق officialPeriods: 3. لا تعرض أربع حصص بوصفها تخصيصًا رسميًا. لكل حصة مجموع خطوات 40 دقيقة، ولا يعوض اختلاف الزمن بمجرد تغيير عنوان اللقاء.

## تطوير في المتصفح

المحرر يسمح بتحسين الشرح والمثال والمهمة والتدخل والتقويم لكل حصة. يزامن الخطوات ذات الخمس مراحل مع النص المعدل، ويبقي الأهداف والاسم الرسمي كما هما. تغيير الأهداف أو إضافة أسئلة متعددة الخيارات يتم في catalog.json بعد مراجعة المصدر، أو عبر حزمة محررة ثم مستوردة. يرفض التحقق خيار إجابة خارج حدود الأسئلة.

لتضيف سؤالًا، ضع في quiz:

```json
{
  "question": "سؤال يرتبط بهدف موثق",
  "options": ["اختيار أول", "اختيار ثان", "اختيار ثالث"],
  "answer": 1,
  "explanation": "تفسير يوضح سبب الاختيار ويساعد على المراجعة."
}
```

answer يبدأ من صفر؛ المثال يعني الاختيار الثاني. كل سؤال له تفسير؛ لا تضف سؤالًا للتزيين أو يقيس معلومة خارج المصدر.

## إصدار حزمة

صدّر من استوديو المتصفح. انقل catalog إلى content/catalog.json ثم نفذ npm test وnpm run build. البناء ينشئ assets/catalog.js ومكتبة الإضافة وحزمة downloads. ادفع الملفات إلى GitHub لإصدار موقع متوافق. لا تعدل الملفات المولدة وحدها لأن البناء سيستبدلها.


المكتبة المرفقة حاليًا تشمل الصفوف 5 و6 و7 و8 و9 و10 و12. للعاشر خمسة دروس ويب، وللثاني عشر تسعة دروس من الوحدتين الأولى والثانية؛ مشروع العاشر ومشاريع الوحدة الثالثة للثاني عشر لم تكتمل بعد. يمكن نقل التعديلات المحلية بتصدير الحزمة واستيرادها في الإضافة.
